# Project workflow

- Product name: brain off. Repository: https://github.com/guoxinyi0811/brain-off.
- Approved visual direction: precise, flat refrigerator line drawing with restrained silver-blue selection highlights inspired by interior lighting. Keep most of the UI near-white, ink and gray. No neon, glow, shadows, decorative cards, slogans or redundant labels. Colors are visual preferences rather than fixed hex requirements. Expiration must use text/symbols as well as styling, separately from selection.
- The current refrigerator configuration follows the supplied photos: four chilled shelves, one crisper, three freezer drawers, and five asymmetrical door baskets. Shelf 1 is groceries; shelf 2 eggs/raw meat; shelf 3 jarred condiments; shelf 4 cooked food/leftovers. Door geometry follows the photo's staggered arrangement; do not force a grid. Keep SVG geometry in configuration, separate from inventory. Do not commit the personal reference photos.
- Preserve stable location IDs and existing expiration provenance when upgrading configuration. Configuration revision 2 is applied once to the old sample fridge; later user edits must not be overwritten on reload.
- The owner has authorized uploading project files and syncing each completed, verified project update to this repository. Use the GitHub connector or Git CLI when available; browser upload is a fallback.
- Run `npm test` and `npm run typecheck` for domain/code updates before syncing. Inspect changes and exclude node_modules, secrets, personal files and scratch artifacts.
- Keep user requirements, approved decisions, assistant proposals and unresolved questions distinct. Do not expand milestone scope implicitly.
- Cloud synchronization is required eventually, but is deferred beyond milestone 1.
- Inventory stage includes name search, location/expiration filters, sorting and result-to-fridge positioning. Preserve expiration provenance when editing from filtered results. Cross-device synchronization remains unimplemented; docs/cloud-sync-plan.md is a proposal, not an approved provider or deployment decision.
- Website deployment, GitHub Releases and public visibility changes require separate authorization.
- Confirmed expiration input: manual remaining days/weeks, or manufacturing date plus shelf life; missing inputs trigger type-based estimation only where a reviewed rule exists. Preserve original dates/provenance, support legacy exact dates, and never renew an untouched record during edits. Unknown estimates are null and visibly pending, never implicitly safe. Voice recognition into editable inventory drafts is future scope, not implemented.

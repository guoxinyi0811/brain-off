# Project workflow

- Product name: brain off. Repository: https://github.com/guoxinyi0811/brain-off.
- Approved visual direction: precise, flat refrigerator line drawing with restrained silver-blue selection highlights inspired by interior lighting. Keep most of the UI near-white, ink and gray. No neon, glow, shadows, decorative cards, slogans or redundant labels. Colors are visual preferences rather than fixed hex requirements. Expiration must use text/symbols as well as styling, separately from selection.
- The current refrigerator configuration follows the supplied photos: four chilled shelves, one crisper, three freezer drawers, and five asymmetrical door baskets. Shelf 1 is groceries; shelf 2 eggs/raw meat; shelf 3 jarred condiments; shelf 4 cooked food/leftovers. Door geometry follows the photo's staggered arrangement; do not force a grid. Keep SVG geometry in configuration, separate from inventory. Do not commit the personal reference photos.
- Preserve stable location IDs and existing expiration provenance when upgrading configuration. Configuration revision 2 is applied once to the old sample fridge; later user edits must not be overwritten on reload.
- The owner has authorized uploading project files and syncing each completed, verified project update to this repository. Use the GitHub connector or Git CLI when available; browser upload is a fallback.
- Run `npm test` and `npm run typecheck` for domain/code updates before syncing. Inspect changes and exclude node_modules, secrets, personal files and scratch artifacts.
- Keep user requirements, approved decisions, assistant proposals and unresolved questions distinct. Do not expand milestone scope implicitly.
- Cloud synchronization is required eventually, but is deferred beyond milestone 1.
- Inventory stage includes name search, location/expiration filters, sorting and result-to-fridge positioning. Preserve expiration provenance when editing from filtered results. Cross-device synchronization remains unimplemented; docs/cloud-sync-plan.md is a proposal, not an approved provider or deployment decision.
- Website deployment, GitHub Releases and public visibility changes require separate authorization.
- Confirmed expiration input: manual remaining days/weeks, or manufacturing date plus shelf life; missing inputs trigger type-based estimation only where a reviewed rule exists. Preserve original dates/provenance, support legacy exact dates, and never renew an untouched record during edits. Unknown estimates are null and visibly pending, never implicitly safe. Voice-assisted entry into editable drafts is now implemented through the browser recognition service and a typed fallback; see docs/voice-entry.md.
- Daily-use stage supports optional quantities/units and explicit purpose-based placement suggestions. Do not infer quantity 1 for legacy records, merge batches, sum mixed units, or move food when typing or changing purposes. Recommendation matches are organizational, not food-safety assessments. Cloud sync is not implemented.

- Backup stage supports local JSON export, validated full-replacement previews and one persistent pre-replacement recovery point. The default IndexedDB adapter must commit checkpoint and primary data atomically, retaining exact original bytes and quantity/expiration provenance on failures. Never silently merge imports or treat a browser checkpoint as a downloaded/off-device backup. Preserve the observed-change checks; they are not full cross-tab synchronization.

- IndexedDB is now the default local repository. Preserve revision compare-and-swap for all saves/restores, atomic checkpoint rollback and one-time migration archives. Never silently reset/reseed corrupt records or fall back to stale LocalStorage. Keep drafts intact on external updates; reload requires closing dialogs. Legacy source divergence requires explicit reviewed backup reconciliation. See docs/storage-design.md.

- Voice-assisted draft entry is optional and only for new records. Never start capture without a user click, auto-save recognition, invent missing production years, silently resolve ambiguous dates/locations, or request microphone permission during automated QA. Preserve optional entry-source metadata through edits/backups. Keep typed fallback and disclose browser online processing. Live microphone and interactive UI verification remain pending because the host browser kernel failed to initialize in this stage.

- Refrigerator previews are read-only, bounded summaries with date/name/ID ordering. Keep record counts distinct from quantities and preserve separate batches/units. Mobile detail navigation must be explicit and focus the existing detail panel. Retain all 13 physical regions and the independent door geometry. Current map markup is covered by automated rendering tests; visual, touch and focus/scroll browser QA remains pending due to the host runtime initialization failure.

- One-food entry supports punctuation-free explicit field phrases. Preserve punctuated input and the applied raw transcript. Complete production phrases must match uniquely; do not take the first date from alternatives or confirm uncertain/missing-year dates. Parsing errors leave the existing unsaved form unchanged. This remains a limited rule parser, not general natural-language understanding.
